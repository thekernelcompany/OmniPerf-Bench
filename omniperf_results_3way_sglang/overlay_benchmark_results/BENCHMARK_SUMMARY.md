# SGLang 3-Way Benchmark Results

## Overview

This directory contains 3-way benchmark results comparing:
1. **Baseline** - Parent commit before optimization
2. **Human** - The optimization commit from the SGLang repository
3. **Agent Variants** - Patches generated by AI coding agents applied to baseline

## Methodology

Using Python overlay approach inside Docker:
- Base Docker image: `sglang-rebuilt-2a754e57` (SGLang 0.1.17 era dependencies)
- Clone SGLang repo, `git fetch` specific commits
- Use `PYTHONPATH` to overlay Python code without rebuilding
- Run `bench_latency.py` for consistent benchmarking

## Results: Commit 2a754e57 (PR #579)

**Subject**: "2x performance improvement for large prefill & Fix workspace conflicts"

### Benchmark Configuration
- Model: TinyLlama/TinyLlama-1.1B-Chat-v1.0
- Batch size: 4
- Input length: 1024 tokens
- Output length: 256 tokens
- GPU: NVIDIA H100 PCIe

### Performance Results

| Variant | Total Throughput | Decode Throughput | vs Baseline |
|---------|------------------|-------------------|-------------|
| baseline | 1735.85 tokens/s | 350.65 tokens/s | - |
| **human** | **2126.74 tokens/s** | **430.86 tokens/s** | **+22.5%** |
| claude_code | 1743.12 tokens/s | 352.18 tokens/s | +0.4% |
| **codex** | **2095.89 tokens/s** | **424.22 tokens/s** | **+20.8%** |
| **trae_gpt5** | **2158.62 tokens/s** | **437.07 tokens/s** | **+24.4%** |

### Key Findings

1. **Human optimization effective**: The human commit provides +22.5% throughput improvement
2. **trae_gpt5 outperforms human**: Achieved +24.4% improvement (best agent)
3. **codex competitive**: Nearly matches human at +20.8%
4. **claude_code patch issue**: Patch may not have applied correctly (same as baseline)

## Technical Notes

### Patch Application
- Patches are applied to base commit using `git apply`
- Some patches may fail due to context mismatch
- Codex and trae_gpt5 patches show modified files (M markers)
- claude_code patch shows no modifications (possible silent failure)

### Run Variability
- Results can vary between runs (~5-10% variance typical)
- For production benchmarks, multiple runs should be averaged
