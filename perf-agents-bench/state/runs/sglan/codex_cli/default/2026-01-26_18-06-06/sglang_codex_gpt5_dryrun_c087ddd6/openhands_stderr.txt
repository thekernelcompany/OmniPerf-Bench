+    dtype_map = {

What I changed
- python/sglang/srt/layers/moe/ep_moe/kernels.py
  - Pre-reorder scatter: Reordered loops to load each input block once and scatter to all selected experts, avoiding repeated reads for every top-k expert.
  - Post-reorder combine: Removed the redundant zero-fill pass that doubled memory traffic when no local experts were selected. The main pass already writes zeros.
  - Preprocess mapping: Increased compute_src2dst tile size from 512 to 1024 to reduce kernel launch overhead and index math.
- benchmark/kernels/fused_moe_triton/benchmark_ep_pre_reorder_triton.py
  - New microbenchmark to measure the pre_reorder_triton_kernel end-to-end on CUDA across common shapes and dtypes.

Why these help
- Single-load scatter in pre_reorder reduces global reads by ~topk× for each block of the source token vector.
- Removing the second zero-fill pass in post_reorder halves memory traffic for the no-local-expert case.
- Larger tile in compute_src2dst reduces grids and per-tile index overhead without changing correctness.
