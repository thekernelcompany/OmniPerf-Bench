- python/sglang/srt/managers/expert_location.py
  - Make logical_to_rank_dispatch_physical_map lazy (Optional) to avoid computing it when using non-static algorithms.
  - Add ensure_rank_dispatch_map_cached() to materialize the static map on demand.
  - Replace the O(num_gpus) Python-looped compute_logical_to_rank_dispatch_physical_map() with a vectorized, single-rank version:
    - Precomputes physical→gpu mapping.
    - Picks same-GPU candidates when available; otherwise uniformly samples among valid candidates.

  - Build the static per-rank dispatch map lazily via ensure_rank_dispatch_map_cached() only when ep_dispatch_algorithm == "static".
  - Vectorize dynamic dispatch selection:
    - Use a single gather from a uniform random index over the valid physical experts for each logical id.
    - Removes per-element randint/modulo and reshaping overhead.

Why this improves performance
- Skips heavy static-map computation during rebalancing when using dynamic/fake dispatch (common in non-static setups).
- Replaces nested Python loops and large intermediate tensors with vectorized operations on GPU tensors, reducing CPU overhead and memory traffic.
- Keeps the same external behavior: static prefers same-GPU mapping; dynamic/fake uniformly distribute among valid physical experts.

- All public entry points and behavior remain intact.
- The optional static-map field is internal; callers use ExpertLocationDispatchInfo which now computes the map lazily when needed.
