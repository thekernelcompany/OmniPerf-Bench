codex
Implemented targeted performance improvements in the Mooncake disaggregation path.

What I changed
- Faster queueing
  - Added FastQueue in python/sglang/srt/disaggregation/utils.py: a lightweight deque+Condition queue that avoids Queue’s task accounting overhead; compatible with queue.Empty.
  - Switched prefill transfer_queue in python/sglang/srt/disaggregation/mooncake/conn.py to use FastQueue.

- Lower CPU spin
  - transfer_thread in MooncakeKVManager now blocks on get(timeout=1.0) instead of tight 10ms polling; reduces busy-wait CPU while preserving responsiveness.
  - Threads that run bootstrap/transfer/heartbeat/decode are daemonized to reduce shutdown overhead and lingering threads.

- Reduced Python conversion overhead
  - group_concurrent_contiguous in utils.py now returns lists of NumPy arrays instead of lists of Python lists, cutting per-chunk conversions while keeping the downstream usage intact (uses len() and first element only).

Why this helps
- Queue contention is common in hot transfer paths; swapping to a minimal queue reduces lock ops and bookkeeping in high-throughput scenarios.
- Blocking waits eliminate constant wakeups when the queue is empty, decreasing CPU usage without increasing latency on work arrival.
- Avoiding .tolist() reduces allocations and Python object churn when iterating contiguous index runs across layers.

API compatibility
- Public signatures preserved.
- group_concurrent_contiguous still returns two lists; each element remains indexable and sized (now NumPy arrays instead of Python lists), and existing call sites already use len() and [0].

- python/sglang/srt/disaggregation/mooncake/conn.py
