codex
Implemented performance-focused optimizations in the LoRA manager and memory pool without changing the public API.

What I changed
- LoRA batch setup (python/sglang/srt/lora/lora_manager.py)
  - Avoids unnecessary cumsums and synchronizations:
    - Uses arange to build seg_indptr when all segments have length 1.
    - Computes max_len only when needed; gets scalar with .item() to avoid syncs.
  - Reduces Python/GPU round-trips:
    - Vectorizes buffer-id collection into a single tensor via as_tensor.
    - Deduplicates per-adapter metadata writes (rank, scaling) using a set.
  - Uses lean dtypes and the model device:
    - int32 for indices and lengths; float32 for scalings on the model’s device.
  - Caches weight-name resolution:
    - Stores resolved weight name on the module to avoid repeated string searches.

- LoRA memory pool (python/sglang/srt/lora/mem_pool.py)
  - Adds lightweight caches for hot-path lookups:
    - stacked-multiply per weight name.
    - weight-name resolution for A/B names.
    - module_name → normalized weight name per layer.
  - Cuts launch overhead and copies:
    - Uses in-place zero_ instead of assignment for empty adapter slot.
    - Uses non_blocking=True on copy_ to enable async H2D when pinned.
  - Minimizes attribute lookups in tight loops via local bindings.
  - Keeps tensor shapes/dtypes identical; no API changes.

Why this helps
- Fewer device synchronizations and repeated computations reduce latency per batch.
- Vectorized, deduped metadata setup and cached string mapping cut Python overhead in critical paths.
- In-place operations and potential async copies improve memory traffic and overlap.

Notes
- Kernels already operate on int-based indices; switching to int32/float32 for batch info keeps compatibility and saves bandwidth.
- All changes preserve existing behavior; only internal efficiency improved.
